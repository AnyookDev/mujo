Order of work

1
models/ — no dependencies on other large files
Split first because app.rs, handlers.rs, and ui.rs all import from it. Getting the module boundary right here makes the later splits cleaner.
models/mod.rsmodels/entry.rsmodels/totp.rsmodels/editor.rsmodels/menu.rsmodels/sync.rs
2
app/ — split the God object's impl blocks
Move groups of impl App methods into sub-files one domain at a time. Start with git_ops.rs (most self-contained), then clipboard, nav, entries, editor. Run cargo test after each move.
app/mod.rsapp/git_ops.rsapp/clipboard.rsapp/nav.rsapp/entries.rsapp/editor.rsapp/menu.rs
3
handlers/ — one file per mode
These are free functions with no shared state, making them the safest to move. Each handler goes to its own file; handlers/mod.rs re-exports them all so main.rs and other callers need no changes.
handlers/mod.rshandlers/normal.rshandlers/editor.rshandlers/git.rshandlers/dialogs.rshandlers/help.rs
4
ui/ — split the rendering layer last
Leave ui.rs for last because it has the most internal cross-references (private helpers shared between draw functions). Once models/ is clean, the type imports are simpler. Move one draw_* function at a time.
ui/mod.rsui/glyphs.rsui/hints.rsui/status_bar.rsui/sidebar.rsui/editor.rsui/git.rsui/help.rsui/qr.rs

Ground rules

→ Convert src/foo.rs to src/foo/mod.rs by renaming the file. The module path stays crate::foo — no changes to lib.rs or callers.
→ No behavior changes in this refactor. If a function's body needs changing, that's a separate commit.
→ Run cargo test after every file move, not just at the end of each phase. The test suite is the safety net.
→ Items that are currently pub(super) or private may need to become pub(crate) when moved into a sub-file — only widen visibility as far as needed.
→ Shared private helpers (e.g. hslice_spans in ui.rs) belong in the mod.rs of their module, not in every file that uses them.
→ One git commit per phase. Reviewing a 200-line commit of pure file moves is much easier than a 2000-line one.
